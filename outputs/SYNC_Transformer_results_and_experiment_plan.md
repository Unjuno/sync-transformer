# SYNC Transformer: 結果整理と実験計画

## 1. 基準プロトコル

- 現行の基準は、共通再構成ランナー、3 seeds (163/164/165)、60/20/20 split、K=8、固定距離ゲートを用いる。
- 以下の差分はすべて `SYNC - 比較対象` の平均 MSE差分。負値はSYNCのMSEが低く改善、正値は悪化を意味する。
- 旧スクリプトや旧ログにある値は、現行の決定論的プロトコルと一致しない場合、歴史的記録として扱い、主張の根拠には使わない。

## 3. 何が分かったか

1. 現行設定では全データセットで一貫した精度向上はない。
2. ETTh1/ETTm1では、現行SYNCは比較対象および季節ナイーブに劣る。
3. ETTm2では改善が再現するが、外部比較なしでは一般理論とは言えない。
4. ETTh2では安全側の全棄却が起きており、これは性能向上ではなく不確実性制御の挙動である。
5. K>1の候補集約はETTh1/ETTm1の害をやや減らすが、普遍的な救済ではない。
6. split変更で符号が反転するため、時間分割への依存が大きい。
7. マルチスケール表現単独、距離ゲート単独、幅拡大は決定的な寄与として採用できない。
8. 元のPhase4A–4B結果を完全再現したとは言えず、現在の成果は「共通プロトコルによる再構成結果」である。

## 4. 現時点で棄却・未確定の主張

- 「SYNCは常に予測精度を改善する」：棄却。
- 「検索だけで改善する」：支持されない。
- 「距離ゲートで分布シフトを解決できる」：未支持。
- 「季節性を取り込めば既存ベースラインを超える」：現状は棄却。
- 「新規性が確立した」：未確定。広義の検索拡張予測は既知であり、残差輸送・因果的適格性・明示的棄却・クエリ単位監査の組合せが候補だが、RAFT/RAFとの同条件比較が必要。

## 5. 実験計画（優先順位順）

### P0: 基準の凍結と監査（完了扱い）

- canonical suite、全テスト、再構成アーティファクト検証、公開SYNC監査を実行。
- 結果表・ハッシュ・実行条件を保存。
- 以後、主張は本書の表と対応するJSONだけを参照する。

### P1: 外部ベースライン比較（最優先・未完了）

- RAFT公式実装を同一データ、同一予測長、同一評価窓へ移植。
- CPUではスモークテストのみ、最終比較はGPU実行を前提とする。
- 判定条件：SYNCが少なくとも1データセットで、季節ナイーブ・raw retrieval・RAFTを含む比較群に対して、95% CIと計算量を併記して優位性を示す。示せなければ「条件付き安全性／監査性」の主張へ限定する。

### P2: 汎化検証（P1と並行可能）

- rolling-origin評価、完全held-out期間、複数予測長を追加。
- splitごとの符号反転を記録し、平均だけでなく分散・棄却率・改善クエリ率を報告。
- 判定条件：改善が特定splitだけに依存しないこと。依存する場合は、適用条件を明示して一般化主張を止める。

### P3: 機構アブレーション

- 同一候補バンクで、raw retrieval / residual transport / fusion / gate / abstention を一要素ずつ除去。
- K、特徴量、ゲート閾値、モデル幅を事前登録した範囲で再評価。
- 判定条件：残差輸送または棄却が、候補検索単独とは独立した寄与として再現すること。

### P4: 論文化・名称固定

- 名称は **SYNC Transformer** に固定。
- 「新しい予測器」ではなく、「条件付き残差輸送と明示的棄却を備えた検索拡張予測フレームワーク」として記述。
- 限界（季節ナイーブ優位、split依存、ETTh2全棄却、RAFT未比較）を本文に明記。

## 8. CPUで追加したrolling-origin結果

評価対象を時系列の後半全体に固定せず、3つの連続した評価窓で測定した（ETTm1、endpoint+seasonal、K=8、3 seeds）。`SYNC - head` の平均差分は次の通り。

| 学習/較正/評価の割合 | 平均差分 | 改善クエリ率 |
|---|---:|---:|
| 50/60/60–70% | +0.087293 | 21.3% |
| 60/70/70–80% | -0.026214 | 69.0% |
| 70/80/80–90% | -0.014727 | 50.0% |

評価窓によって符号が反転した。したがって、現時点のSYNCは定常的な優位性ではなく、時間的レジームに依存する条件付き機構として扱う必要がある。この結果は `common_runner_ETTm1_*_ev*.json` に保存した。

同じ手順をETTm2にも適用した。平均差分は、50/60/60–70%で +0.001540、60/70/70–80%で +0.106348、70/80/80–90%で -0.006505だった。ETTm2でも評価窓依存性が確認され、改善は最後の窓に限られる。したがって、ETTm2の改善も普遍的効果ではなく、局所的なレジーム適合として扱う。

さらに系列末尾の90–100%区間を評価したところ、ETTm1は -0.002287、ETTm2は -0.003313だった。末尾区間では両方とも小幅改善だが、効果量は小さく、他の窓での悪化を打ち消すほどではない。

コード変更後の全テストは **44 passed**。

集計は `work/summarize_rolling_origin.py` で再現でき、集計済みデータは `outputs/rolling_origin_summary.json` に保存した。

ETTh系についても代表窓（70/80/80–90%、step=24）を追加した。ETTh1は平均 -0.040690、改善クエリ率48.6%だった一方、ETTh2は全クエリ棄却で差分0.0だった。ETTh1でも窓によって改善が現れるため、全データセットに共通する定常的優位性とはまだ言えない。

CPU段階の完了監査：再構成アーティファクト検証は74ファイル・216行でエラー0、公開SYNC監査は全チェック成功、pytestは44 passed。

GPU拡張の再開手順は `outputs/SYNC_Transformer_GPU_extension_plan.md` に固定した。

## 9. 初期に提示されたPhase 4A–4B結果（歴史的・別プロトコル）

初期資料には、ETTh1単独・24時間先・3 seeds・720時間履歴・候補82個の内部検索比較が含まれている。この結果は現行canonical runnerでは再実装されていないため、現行主結果と混ぜず、別プロトコルの既存エビデンスとして保持する。

| 方式 | MSE |
|---|---:|
| Base Transformer | 0.4378 |
| External Sync | 0.3868 |
| Internal E2E | 0.3939 |
| Internal Ranked | 0.3858 |
| Hierarchical Internal | 0.3849 |
| Raw retrieval | 0.4299 |
| Seasonal baseline | 0.4335 |
| Oracle candidate | 0.2420 |

初期資料の主張は、Internal Ranked−External Sync = -0.00106、95% CI [-0.00257, +0.00039]で統計的に同等、ranking lossはInternal E2Eから -0.00819（CI [-0.00983, -0.00655]）、逆順軌道介入は約+0.0869悪化、External Syncは約5.72 ms、Internal Rankedは約22.29 msだったというもの。これは「外部保存そのものは精度に必須ではないが、検索演算を予測器から分離すると高速」という、SYNCの設計上重要な仮説を支持する。

ただし、単一データセット、CPU、候補間隔8時間、GPU最適化未検証であり、再現コード・統合JSONが現行成果物に存在することはまだ確認できていない。したがって論文化では、再現できるまで数値を主結果にせず、「再検証待ちの初期結果」と明記する。CPUで可能な次の追加実験は、このPhase 4A–4Bの最小再実装と、軽量埋め込み検索→top-k融合の速度比較である。

なお、旧Phase 157–215の再構成診断はワークスペース内に残っている。ETTh1の学習queryとcandidate bankを分離した同一query比較では、Internal E2E−External = +0.006151（CI [+0.004176,+0.008156]）、Internal Ranked−External = +0.008400（CI [+0.006108,+0.010776]）で、現行再構成では内部方式は外部方式を上回らなかった。これは初期資料のInternal Ranked優位（-0.00106）と矛盾するため、初期実装との差分が未解明である。この矛盾自体を重要な再現性課題として記録し、どちらか一方を恣意的に採用しない。

Phase 157/158の最小スクリプトは再実行でき、保存値と一致した（Internal E2E MSE 11.90217、Internal Ranked MSE 12.64449）。ただしこれは正規化解除後の別診断プロトコルで、初期の0.3939/0.3858とは尺度・候補構成が異なる。したがって「再現不能」ではなく、「複数の再構成プロトコルが存在し、初期結果との対応が未確立」という状態である。
